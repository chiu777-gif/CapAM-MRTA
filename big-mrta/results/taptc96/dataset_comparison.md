# 为什么 TAPTC 完成率更低，但 BiG-MRTA 适配版 cost 更小？

复核结论：没有发现原始场景读取、单位转换、任务遗漏或 cost 计算错误。这里较小的 cost **不代表 TAPTC 更容易**。原因是该指标同时计算逾期任务数量和逾期程度，而且这些有限 cost 属于 `capam_full_visit` 适配版。

## 直接复算 cost

每个场景 100 个任务，cost 定义为：

```text
cost = Σ_{finish_i > deadline_i} finish_i / deadline_i
     = 逾期任务数 + Σ_{逾期任务} (finish_i - deadline_i) / deadline_i
```

因此，逾期任务更多并不必然使 cost 更大。例如，一个任务以截止时间的 5 倍完成，cost 为 5；两个任务都以截止时间的 1.1 倍完成，cost 仅为 2.2。

| 统计量（全任务适配版） | 训练同分布 1000 场景 | 原始 TAPTC 96 场景 |
|---|---:|---:|
| 按时完成率 | 70.892% | 56.167% |
| 每场景平均逾期任务数 | 29.108 | 43.833 |
| 每个逾期任务平均 `finish/deadline` | 4.156384 | 2.650942 |
| 平均 cost | 120.984025 | 116.199606 |
| cost 中的平均逾期任务数项 | 29.108 | 43.833 |
| cost 中的平均归一化超时项 | 91.876025 | 72.366272 |

这里“每个逾期任务平均比值”按全部逾期任务加权，故有：

```text
训练同分布：29.108 × 4.156384 ≈ 120.984
TAPTC：    43.833 × 2.650942 ≈ 116.200
```

TAPTC 的任务更常逾期，但训练同分布数据中被本适配策略拖到逾期的任务具有更高的归一化超时惩罚。

## 原始数据与逾期任务分布

TAPTC 原始工作量全部为 20；有效机器人的能力只有 1 或 2，按有效机器人汇总的平均能力为 1.411765。训练同分布数据的工作量来自 `[10,30]`，能力来自 `[1,3]`，实际有效机器人平均能力为 1.998725。两套数据并非只改变了截止时间。

| 统计量 | 训练同分布 | TAPTC |
|---|---:|---:|
| 全部任务的平均 deadline（秒） | 325.015 | 301.037 |
| **逾期任务**的平均 deadline（秒） | 183.288 | 246.049 |
| **逾期任务**的平均完成时间（秒） | 575.831 | 592.131 |

不能用完成时间的平均值除以 deadline 平均值替代平均 `finish/deadline`。上表描述的是本算法实际留下的逾期任务子集，而非整个数据集的难度排序。

## 排除机器人数量混合比例这一解释

训练同分布数据包含 2–7 个机器人，而 TAPTC 只有 2、3、5、7 个机器人。限定这四个共同组并各赋 25% 权重后：

| 指标 | 训练同分布（共同组等权） | TAPTC |
|---|---:|---:|
| 平均 cost | 140.246108 | 116.199605 |
| 完成率 | 67.784% | 56.167% |

倒挂仍然存在，所以它不只是样本组别占比造成的。各组来自不同场景，这不是对同一地图的成对难度实验。

## 有限 cost 的复现边界

原始 BiG-MRTA 允许不分配任务，其完整解 cost 为 `null`。表中有限 cost 来自本目录的适配版：在原策略返回 0 时临时放宽 deadline，继续分配全部任务。

训练同分布数据中，这类放宽后分配的任务平均贡献 cost 117.519333，占总 cost 约 97.14%；TAPTC 中贡献 115.656095，占约 99.53%。因此，有限 cost 很大程度取决于适配策略如何完成原算法未安排的任务，不能直接等同原论文未修改 BiG-MRTA 的性能。

作为交叉核对，现有同一 CapAM epoch-97 结果在训练同分布数据上的 cost 为 58.538374、完成率 67.444%；在 TAPTC 上的 cost 为 116.975896、完成率 46.406%。这里两个指标都变差。不同策略会产生不同的逾期任务及超时程度。

## 本次核验

- 核对两个数据源的 SHA256；TAPTC 仅包含 96 个任务文件及其对应的 12 个机器人文件，未混入 `n_200` 或演示样例。
- 96 个 TAPTC 场景的坐标、工作量、能力、机器人起点和 deadline 均与原始文本逐项一致；公共加载器的尺度变换也已逐项核对，deadline 未缩放或替换。
- 两套数据的 1096 条完整路线均包含全部 100 个任务且没有重复分配。
- 使用原始物理单位、float64、独立逐机器人累计时间重放所有路线，**按时/逾期分类差异为 0**。
- 与原来 float32 公共仿真器相比，最大完成时间误差：训练同分布 0.000667 秒，TAPTC 0.000351 秒；最大单场景 cost 误差分别约 0.000070 和 0.000036，仅为浮点累计误差。
- 从逐任务完成时间重新计算的平均 cost 与报告一致。

机器可读的统计、文件哈希和核验误差见 [dataset_comparison_audit.json](dataset_comparison_audit.json)。本次没有修改算法、数据、已有路线或已报告的数值。
